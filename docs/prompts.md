# claude

Проект: сервис для совместного просмотра видео

Стек:
- Go (backend)
- Nginx
- csv based storage
- client: html/css/js

Архитектура:
- api на ws для чата
- всё разворачивается на VPS

Текущая ситуация:
- авторизация отсутствует

Требование:
- реализовать session-based auth
- без JWT
- с поддержкой нескольких пользователей

Ты — senior backend инженер (Go), специализируешься на микросервисной архитектуре и системах аутентификации.

Я разрабатываю проект, описание выше.

Задача:
спроектировать session-based систему регистрации и авторизации.

Мне не нужен код.
Мне нужно принять архитектурные решения.

Ответ должен включать:

1. Общую архитектуру решения
   - как будет устроена сессия
   - где хранится (in-memory / Redis / DB)
   - как происходит создание и проверка

2. Поток регистрации и логина (пошагово)

3. Структуру данных
   - пользователь
   - сессия

4. Как обрабатывать:
   - logout
   - истечение сессии
   - несколько устройств

5. Безопасность:
   - cookies (httpOnly, secure и т.д.)
   - защита от CSRF
   - хранение паролей

6. Альтернативы и почему выбран именно этот подход

7. Итог в виде краткой спецификации,
   которую можно дать другому разработчику или AI-агенту для реализации

Если есть несколько вариантов — сравни их и предложи лучший для моего кейса.

Сформируй финальную спецификацию в формате:

- overview
- components
- API endpoints
- data models
- flow diagrams (текстом)
- edge cases

Так, чтобы это можно было напрямую использовать для реализации
